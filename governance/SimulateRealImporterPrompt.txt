CHAPTER 3: DISCOVERY PROTOKOL
=============================================================

Cíl: zjistit, které sportovní tabulky v VO2QNAPDBAI existují, aby bylo kam importovat.

## Krok 1 — list_tables (VO2QNAPDBAI)
Filtruj tabulky končící na "Matches" nebo "Races".

  importColumns = průnik dstSchema ∩ srcSchema (case-insensitive porovnání názvů)
  Opakovat pro Teams, Players, Leagues, LeagueSeasons (pokud tabulky v VO2QNAPDBAI existují).

CHAPTER 4: DEDUP CHECK PROTOKOL
=============================================================

Před každým zápisem ověř existenci dle business klíče — ne Id.
Důvod: tabulky mohly být naplněny jinými agenty bez SR Id → upsert dle Id = duplicita.

## BULK DEDUP (preferovaný způsob — redukuje SQL volání 10–50×)

Pro každou entitu místo row-by-row SELECT použij bulk přístup:
  1. Načíst existující záznamy najednou (LIMIT 5000):
     SELECT "Id", LOWER("{nameCol}") AS n, "{countryCol}" AS c FROM "{Sport}Teams"
  2. Porovnat in-memory s importovanými daty (LOWER normalizace)
  3. Sestavit dvě sady: toInsert[] a toUpdate[]
  4. Zapsat dávkově: smart_upsert_batch(toInsert, batchSize=100)
                     smart_upsert_batch(toUpdate, batchSize=100)

Pro Matches (kde je potřeba přesný čas):
  Bulk SELECT: SELECT "Id", "{dateCol}", "{homeCol}", "{awayCol}" FROM "{Sport}Matches"
               WHERE DATE("{dateCol}") IN ({seznam datumů z importu})
  → porovnat in-memory → INSERT/UPDATE

Fallback (pokud smart_upsert_batch nedostupný):
  Dedup check = run_select_sql na VO2QNAPDBAI s WHERE podmínkou dle business klíče.
  0 řádků → INSERT nový záznam
  1+ řádků → UPDATE existujícího (upsert_record s Id z výsledku)

Normalizace jmen: vždy LOWER() — accenty a překlepy mohou přesto způsobit duplicity,
ale fuzzy matching se nepoužívá (příliš pomalý na velkých objemech). Přijatelná tolerance.

SyncedAt: pokud sloupec "SyncedAt" existuje v dstSchema → vždy nastav na now() při každém zápisu
(INSERT i UPDATE). Nezapisuj SyncedAt ze zdrojových dat SportReal.

-----------------------------------------------------------
LIGY — business klíč: Name + Country + Sport
-----------------------------------------------------------
Identifikuj v dstSchema:
  nameCol    = první existující z: "Name", "LeagueName"
  countryCol = první existující z: "CountryId", "Country"
  sportCol   = první existující z: "SportId", "Sport", "SportName"

Dedup dotaz (VO2QNAPDBAI):
  SELECT "Id" FROM "{Sport}Leagues"
  WHERE LOWER("{nameCol}") = LOWER('{leagueName}')
    AND "{countryCol}" = {countryVal}
  LIMIT 1

  0 výsledků → insert nová liga → ulož mapování: srLeagueId → dstLeagueId
  1 výsledek → update existující → ulož mapování: srLeagueId → nalezený dstLeagueId

LEAGUE ID MAPPING:
  Po zpracování všech lig sestav in-memory mapu: { srLeagueId: dstLeagueId }
  Při importu Teams, Players, Matches: pokud záznam obsahuje LeagueId,
  přepiš SR LeagueId → dstLeagueId z mapy před zápisem do VO2QNAPDBAI.
  L SR LeagueId není v mapě → zapsat NULL (nezapisovat cizí Id, které v cíli neexistuje).

-----------------------------------------------------------
TÝMY — business klíč: Name + Country
-----------------------------------------------------------
Identifikuj v dstSchema:
  nameCol    = první existující z: "Name", "TeamName", "FullName"
  countryCol = první existující z: "CountryId", "Country", "Nationality"

Dedup dotaz (VO2QNAPDBAI):
  SELECT "Id" FROM "{Sport}Teams"
  WHERE LOWER("{nameCol}") = LOWER('{teamName}')
    AND "{countryCol}" = {countryVal}
  LIMIT 1

  0 výsledků → insert nový tým → ulož mapování: srTeamId → dstTeamId
  1 výsledek → update existujícího → ulož mapování: srTeamId → nalezený dstTeamId

TEAM ID MAPPING:
  Stejný princip jako League ID mapping — sestav in-memory mapu srTeamId → dstTeamId.
  Při importu Matches: HomeTeamId a AwayTeamId přepiš přes tuto mapu před zápisem.
  L SR TeamId není v mapě → přeskočit zápas, log "team_id_not_mapped"

-----------------------------------------------------------
HRÁČI — business klíč: Name + Country
-----------------------------------------------------------
Identifikuj v dstSchema:
  Varianta A (oddělené): "FirstName" + "LastName"
  Varianta B (jedno pole): "Name", "PlayerName", "FullName"
  countryCol = první existující z: "Nationality", "Country", "CountryId"

Dedup dotaz:
  Varianta A:
    SELECT "Id" FROM "{Sport}Players"
    WHERE LOWER("FirstName") = LOWER('{firstName}')
      AND LOWER("LastName") = LOWER('{lastName}')
      AND "{countryCol}" = '{country}'
    LIMIT 1
  Varianta B:
    SELECT "Id" FROM "{Sport}Players"
    WHERE LOWER("{nameCol}") = LOWER('{fullName}')
      AND "{countryCol}" = '{country}'
    LIMIT 1

  0 výsledků → insert nový hráč
  1 výsledek → update existujícího

-----------------------------------------------------------
ZÁPASY — business klíč: HomeTeam + AwayTeam + Date (+ Time)
-----------------------------------------------------------
POZOR: Před zápisem zápasu musí být k dispozici TEAM ID MAPPING (viz Týmy výše).
Bez mapování nelze dedup check provést — přeskočit sport, log "team_mapping_missing".

Identifikuj v dstSchema:
  dateCol = první existující z: "StartTime", "MatchDate", "Date", "KickoffTime"
  homeCol = první existující z: "HomeTeamId", "HomeTeam", "Team1Id"
  awayCol = první existující z: "AwayTeamId", "AwayTeam", "Team2Id"

Dedup dotaz:
  SELECT "Id", "{dateCol}" FROM "{Sport}Matches"
  WHERE DATE("{dateCol}") = '{matchDate}'
    AND "{homeCol}" = {dstHomeTeamId}
    AND "{awayCol}" = {dstAwayTeamId}
  LIMIT 5

  0 výsledků → insert nový zápas
  1 výsledek → update existujícího
  2+ výsledků (stejné týmy hrají 2× za den):
    → Porovnej přesný čas: WHERE "{dateCol}" = '{exactStartTime}' LIMIT 1
    → Nalezen → update toho záznamu
    → Nenalezen → insert nový (jiný čas = jiný zápas)

ZÁVODNÍ SPORTY (Pattern B — bez HomeTeamId/AwayTeamId):
  Dedup dle: RaceId nebo (Date + Stage/Round)
  Vždy nejprve get_table_schema, pak dedup podmínku přizpůsob skutečným sloupcům.

-----------------------------------------------------------
SEZÓNY — business klíč: LeagueId + SeasonLabel (nebo StartYear+EndYear)
-----------------------------------------------------------
Identifikuj v dstSchema:
  seasonCol  = první existující z: "SeasonLabel", "Season", "Name"
  leagueCol  = první existující z: "LeagueId", "League"

Dedup dotaz:
  SELECT "Id" FROM "{Sport}LeagueSeasons"
  WHERE "{leagueCol}" = {dstLeagueId}
    AND LOWER("{seasonCol}") = LOWER('{seasonLabel}')
  LIMIT 1

  0 výsledků → insert nová sezóna
  1 výsledek → update existující

  sr_get_teams(teamTable="{srcTeamTable}", limit=500)
  Pro každý tým: dedup check (Chapter 4 — Týmy), přepiš LeagueId přes leagueId mapping
  → INSERT nebo UPDATE + sestav teamId mapping

## Krok 4d — Players
  run_select_sql(VO2QNAPDBSR): SELECT {importColumns} FROM "{srcPlayerTable}"
    ORDER BY "Rating" DESC NULLS LAST LIMIT 500
  Pro každého hráče: dedup check (Chapter 4 — Hráči)
  → INSERT nebo UPDATE

## Krok 4e — Matches
  L teamId mapping chybí → přeskočit Matches pro tento sport, log "team_mapping_missing"
  LastSyncAt = max CompletedAt ze SR_ImporterRuns kde SportName = aktuální sport AND Success=true
  L FirstRun → dateFrom = today - 90 days

  PRE-IMPORT CHECK (úspora při prázdném sportu):
  SELECT COUNT(*) AS cnt FROM "{srcMatchTable}" sr
  WHERE "{srcDateCol}" > '{LastSyncAt}'
  → cnt = 0 → přeskočit sport, log "no_new_data:{sport}", pokračovat dalším sportem

  Stránkovat po 200: sr_get_matches(matchTable=srcMatchTable, dateFrom=LastSyncAt, limit=200, offset=0)
  Pro každý zápas:
    → Přepiš HomeTeamId + AwayTeamId přes teamId mapping
    → Přepiš LeagueId přes leagueId mapping
    → Dedup check (Chapter 4 — Zápasy)
    → INSERT nebo UPDATE
  Opakovat s offset+200 dokud rowCount < 200

## Po importu sportu
  upsert do SR_ImporterRuns:
  { AgentName, SportName, MatchCount, TeamCount, PlayerCount, LeagueCount,
    StartedAt, CompletedAt=now(), Success=true }

CHAPTER 7: ERROR HANDLING
=============================================================

- Tabulka neexistuje v SportReal → přeskočit sport, log "table_not_found_sr"
- Tabulka neexistuje v VO2QNAPDBAI → přeskočit sport, log "no_target_table" (nikdy nevytvářet)
- Průnik sloupců je prázdný → přeskočit tabulku, log "schema_mismatch"
- Dedup sloupce nenalezeny v dstSchema → přeskočit sport, log "dedup_columns_missing", ntfy warning
- League mapping chybí → Matches importovat bez LeagueId (NULL), pokračovat
- Team mapping chybí → přeskočit Matches pro tento sport, log "team_mapping_missing"
- SR TeamId není v mapě → přeskočit zápas, log "team_id_not_mapped"
- VO2QNAPDBAI write error → retry 3× (2s/4s/8s), pak přeskočit záznam, log chyby
- Rate limit VO2QNAPDBSR → počkat 5s, retry
- Celkový run selže → ntfy urgent (topic: agent-errors)
- Partial run → ntfy warning (topic: agent-alerts), uložit co bylo hotové
