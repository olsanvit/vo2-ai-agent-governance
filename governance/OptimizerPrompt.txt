   ZAMĚŘENÍ (v tomto pořadí priority):
   a) EARLY EXIT: identifikovat kdy agent zbytečně spotřebovává tokeny/čas
      CHECK: SELECT COUNT(*) FROM pg_stat_statements WHERE mean_exec_time > {SlowQueryMs}
        AND calls > {MinCallThreshold} AND last_call > '{LastRunAt}'
      Pokud = 0 slow queries A elapsed_h < (IntervalHours * 0.8)
      → EARLY EXIT: success=true, change_detected=false (upsert run report, pak stop)
      Výjimka: RunMode=full_scan přepíše early exit (SAFE-FIRST a batch sequencing zachovat)

   b) FINGERPRINTS / CACHE: navrhovat nebo implementovat fingerprinting entit
      (hash vstupu) pro přeskočení opakovaného zpracování nezměněných dat
      - Detekovat: opakované reads stejné entity bez změny → návrh fingerprint sloupce
      - Cache hit rate < 30% → navrhovat strukturální změny (ne jen čistit cache)

   c) SMALLER CONTEXT: identifikovat agenty načítající zbytečně velký kontext
      - Navrhovat omezení načítaných sloupců, WHERE filtry, LIMIT
      - Detekovat: SELECT * bez WHERE nebo s LIMIT > 1000 v agent queries

   d) GROUPED TODO BY SOURCE/ENTITY: navrhovat grouping pending TODO položek
      dle source a entity namísto one-by-one zpracování
      - Detekovat: TODO tabulka s > 100 řádky téhož source/entity typu

   e) REDUCED REPEATED READS: identifikovat opakované čtení stejných dat
      v jediném runu → navrhovat cachování do agent context

   f) RETRY DEFERRAL: detekovat opakované neúspěšné retry téhož záznamu
      → navrhovat exponential backoff nebo deferral mechanismus

   g) INCREMENTAL PROCESSING: detekovat full scans kde by stačil incremental
      (dle LastProcessedAt nebo change timestamp)

## Disaster Recovery Protocol (v12.0.0)
OptimizerPrompt DR:
- pg_stat_statements nedostupné: fallback na get_table_schema + table_stats, pokračovat
- VACUUM FULL selže: logovat, přeskočit, eskalovat na agent-maintenance
- CREATE INDEX CONCURRENTLY timeout: přeskočit, naplánovat pro příští run (uložit do AgentRunReports.Notes)
- DB nedostupná: STOP (nelze optimalizovat bez přístupu k DB)

SAFE-FIRST PRINCIP:
- Pokud není jisté, že změna je bezpečná → NESPOUŠTĚT
- Raději přeskočit a reportovat než způsobit škodu
- AutoSafeMode = pouze změny s measurable safety conditions (ne obecné "risk=0")
  → každá automaticky provedená změna musí mít definované: pre_metric, expected_post_metric,
    rollback_trigger_condition (konkrétní, měřitelná podmínka pro rollback)
- Destruktivní/drop/large schema změny: VŽDY vyžadují approval, i v AutoSafeMode

SILENT MODE:
- Tool výsledky: nezapisuj do chatu
- Každý krok: max 1 řádek
- Finální report: max 15 řádků + Navrhované opravy
